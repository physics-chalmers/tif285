• We aim to publish the problem sets at least three weeks before the deadline and they will then be accessible for download from the Files tab, or found in the doc/pub directory in the course repository.
  • Problem sets are performed individually. See examination rules on the course web page.
  • Every student must understand their submitted solution in the sense that they should be able to explain and discuss them in detail with a peer or with a teacher.
    • Conditional on the above requirement, students are still allowed to discuss together and to help each other when solving the problems and working on projects.
    • Conditional on the above requirement, students are also allowed to use generative AI tools for coding assistance. The recommended approach is to first write your own code and only use AI tools for debugging or code improvement. You must fully understand the code that is generated and you are encouraged to perform code tests.
  • The two notebooks for each problem set contain a number of conceptual and extra problems; you can choose which and how many to work on.
  • Before you submit your solution, make sure everything runs as expected. First, restart the kernel (in the menubar, select Kernel Restart) and then run all cells (in the menubar, select Cell Run All).
  • Make sure that the run time is smaller than a few minutes. If needed you might have to reduce some computational tasks; e.g. by decreasing the number of grid points or sampling steps. Please ask the supervisors if you are uncertain about the run time.

  • Important remarks: grading and face-to-face discussions: 

    • It is the submission of solution code and results (in the form of a Jupyter notebook) via the Canvas assignment that is considered as your final hand-in solution. See specific deadlines on the corresponding Canvas Assignments. Note that there are separate Canvas Assignments for conceptual and extra problems.
    • Several problems contain tasks that must be pre-graded via the corresponding Yata Question before submission. Such problems are clearly marked and you must have passed the automatic grading in Yata (obtaining a green check mark) before handing in your solution to receive credits. Pre-grading via Yata is mandatory AND you must submit your final solution via Canvas. See specific deadlines on the corresponding Yata Questions assignment.
    • Other problems will only be graded manually. Manual grading is performed in the teacher's python environment, which is based on the conda `environment.yml` file in the course github repo. Therefore you cannot use additional python modules as this will cause import errors.
    • Approved participation in a face-to-face discussion with one of the teaching assistants is mandatory. Time slots will be published on Canvas (distributed over two of the Thursday lab sessions). Your participation is expected in person. You will be expected to answer questions on your code implementation and results. No extra preparation is needed for these discussions apart from familiarity with your own solution.
    • An extended oral examination (covering all aspects of the course) will be arranged with the examiner at the end of the course for students that: (i) do not show up for their discussion slot, or (ii) fail to demonstrate convincing familiarity with their hand-in solutions. This extended oral examination will be organized separately from the project-focused oral examination that all students have.

  • Late submissions

    • Problem sets that are handed in post deadline will be graded at a reduced rate of 2/3 (2 points awarded for every 3 points passed).
    • Late submissions will only be eligible for points corresponding to the minimum required for a passing grade (for Chalmers PhD students this corresponds to grade 4).
    • Late hand-ins will be graded in December/January (handed in before Nov. 30th) or August/September (handed in before July 31st).
